# Локальна модель під класифікатор і дедуп (план)

Мета: винести два **найдешевші-але-найчастіші** LLM-кроки — класифікатор (1 виклик на
кожен елемент) і LLM-дедуп (1 виклик на пачку) — на локальну відкриту модель, щоб
прибрати плату за токени OpenAI на них. Генерацію прози поки лишаємо на `gpt-4o-mini`
(там якість помітна найбільше).

Не будуємо LLM з нуля — беремо готові **відкриті ваги** й запускаємо у себе.

## Чому саме ці два кроки
- **Класифікатор** (`newsroom/analyze/classifier.py`) — найбільший обсяг: 1 виклик/елемент.
  Задача вузька й структурована: `is_event`, `rubrics`, `side`, `is_first_source`,
  `is_rumor` → JSON. Малій моделі це під силу.
- **Дедуп** (`newsroom/editorial/dedup.py`) — групування пачки за однією новиною → JSON.
  Теж структуровано, не потребує frontier-якості.
Обидва вже за pluggable-патерном (Protocol + LLM-реалізація + fake), тож бекенд
підмінюється без переписування пайплайна.

## Модель
- Кандидат №1: **Qwen2.5-7B-Instruct** — сильний мультимовний (укр. включно),
  добре тримає інструкції та JSON, 7B у квантуванні Q4 ~5–6 ГБ VRAM.
- Резерв: Gemma-2-9B-Instruct, Mistral-Nemo-12B, Llama-3.1-8B — перевірити на укр.
- Формат: GGUF Q4_K_M (баланс якість/памʼять). За кращого GPU — 14B для вищої якості.

## Рантайм
- Старт: **Ollama** — має OpenAI-сумісний ендпоінт `http://localhost:11434/v1`,
  підтримує JSON/structured output, тривіальний запуск. `ollama pull qwen2.5:7b-instruct`.
- Пізніше за потреби пропускної здатності: **vLLM** (теж OpenAI-сумісний, вищий тппут).

## Інтеграція (мінімальні зміни)
Наш `LLMClassifier`/`LLMDedupGrouper` створюють `OpenAI(api_key=...)`. OpenAI-клієнт
приймає `base_url` — тож локальна модель підключається зміною base_url + назви моделі:

1. Додати в `LLMClassifier`/`LLMDedupGrouper` параметри `base_url` і читання з env:
   - `CLASSIFIER_LLM_BASE_URL`, `CLASSIFIER_LLM_MODEL` (напр. `qwen2.5:7b-instruct`);
   - `DEDUP_LLM_BASE_URL`, `DEDUP_LLM_MODEL`;
   - не задано → хмарний OpenAI (як зараз).
2. `OpenAI(base_url=<local>, api_key="ollama")` → говорить з Ollama.
3. JSON: якщо локальний ендпоінт не тримає `response_format=json_object` строго — не
   страшно: наші парсери **вже** захищені (повтор + консервативний fallback). За потреби
   ввімкнути structured output Ollama.
4. **Автофолбек**: при помилці/недоступності локального — ретрай на хмарний mini (щоб
   падіння локального сервера не зупиняло пайплайн). Додати простий двоступеневий виклик.

Генерація/курація/факт-чек лишаються на OpenAI (окремі env, не чіпаємо).

## Перевірка якості ДО переходу (обовʼязково)
Малий eval-харнес на реальних даних:
1. Взяти ~300 реальних елементів; еталон — поточні виходи `gpt-4o-mini` (або ручна
   перевірка спірних).
2. **Класифікатор**: узгодженість `is_event`, збіг `rubric`, прапорці rumor/first_source
   vs еталон. Поріг переходу напр. ≥90% по рубриці, без просідання на is_event.
3. **Дедуп**: precision/recall дубль-пар на розміченому наборі (є калібрувальні пари з
   попереднього аналізу). Локальний не має зливати зайве.
4. Порівняти латентність/тппут на цільовому залізі → порахувати реальну вартість
   (GPU $/год ÷ елементів/год) проти mini. Переходимо, лише якщо і якість тримається,
   **і** справді дешевше.

## Розгортання (поетапно, з миттєвим відкатом)
- **Фаза 0**: eval-харнес + вибір моделі (Qwen2.5-7B як старт).
- **Фаза 1**: додати локальний бекенд за env (base_url/model) + автофолбек; дефолт — хмара.
- **Фаза 2**: тіньово — рахувати локальний і хмарний паралельно на вибірці, логувати
  розбіжності; підкрутити промпт під локальну модель.
- **Фаза 3**: перемкнути класифікатор + дедуп на локальний; генерацію лишити на mini.
  Моніторити decisions/якість. Відкат — зміна env назад на хмару.

## Залізо
- Локально: GPU з ~12 ГБ VRAM (напр. RTX 3060 12GB) впевнено тягне 7B Q4.
- Хмара: невеликий GPU (L4/A10). Памʼятати: 24/7 GPU ~$400–700/міс — тож виграш є лише
  за достатнього обсягу; класифікатор (найбільший обсяг) — найкращий кандидат на економію.
- Крихітні моделі можливі на CPU, але для обсягу класифікатора повільно — GPU бажаний.

## Ризики / застереження
- **Українська якість** малих моделей різниться — тому eval обовʼязковий перед переходом.
- **Надійність JSON** нижча за GPT — тримають наші захищені парсери + опційно structured
  output; додати автофолбек на хмару.
- **Опер. навантаження**: тримати/оновлювати локальний сервер; моніторинг доступності.
- **Економія не гарантована** на малому обсязі (простій GPU дорожчий за дешевий mini) —
  рішення за виміром вартості (крок eval №4).
- Дрібниця: `classifier.py` використовує `str.format` (у промпті нема JSON-дужок, тож ок);
  якщо додаватимемо JSON-приклад у промпт під локальну модель — перейти на `fill_prompt`.
